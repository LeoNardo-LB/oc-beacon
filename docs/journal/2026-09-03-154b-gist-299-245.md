## §一 #154b secret gist 全量日志附件——代码落地（单测绿，E2E 待做）

### 可行性裁定（先决问题）

卡片旧前提「需 App 加 Gists 权限+重新授权」的 **App 形态**核实：注册走的是
GitHub App（`scripts/setup-github-report-app.sh` Stage 1 指向 settings/apps/new，
Issues: Read & write + Device Flow）；代码里 `scope=public_repo` 对 GitHub App
本来就被忽略（权限来自 App 配置）。官方文档（docs.github.com/en/rest/gists/gists）
现口径：**Create a gist 支持 GitHub App user access token**（老社区帖 403 是安装
token/旧状态）。故判定可行，真机 E2E 实测 App user token 的 gist 权限定界
（403 → 降级路径 + 用户在 App 设置补权限/重授权；201 → 直接成）。

### 设计决策（4 条硬规则）

1. **附件永不阻塞正文**：`uploadAttachment` 任何失败（含 403/限流/网络）降级为
   无附件继续上报；401 不在此特判——若 token 真失效，后续 issue/comment 步骤会
   以 Unauthorized 上抛引导重授权（spec §失败处理精神延伸）。
2. **防孤儿 gist**：gist 创建排在 24h 防刷判定**之后**——被防抖掉的重复上报
   不得留下孤儿 gist（单测 `suppressed duplicate within 24h creates no orphan gist`
   锁死 exactly=1）。
3. **截断保尾**：gist 单文件上限 ~1MB 是**字节**，CJK 按 UTF-8 最坏 3 字节/字符
   折算 → `MAX_GIST_CONTENT_CHARS = 300_000`（300K×3=900KB 留余量）；超出保尾
   截断（最新日志诊断价值最高），首行加「（前部已截断…）」标注。
4. **scope 参数双形态覆盖**：device code 请求 scope `public_repo` →
   `gist+public_repo`——GitHub App 形态下仍被忽略（零影响），OAuth App 形态下
   gist 生效（若用户实际注册形态与向导不符也能自愈）。

## §二 #245 真机复现尝试（2026-09-03 完成——未复现，注入伪影定界）

**装置**：devDebug（5cdaec94 基线构建）+ debug-entry 冷启 + 「杭州公积金仲裁
资料清单」会话（ses_fec755859…，412 msgs，**当前服务器最大会话**；真实法律
工作会话——全程只读滚动，零发送零交互）。

**前置发现（旧巨型会话已不可达）**：Room 库（704MB）中 15.6 万条巨型会话
（session-a6c42dd8…：5369 缓存 + 150624 归档）属**已下线服务器**——192.168.110.95
不可达（HTTP 000），本机 .248 上 404（且 V2 API 校验 id 前缀 ses）；旧会话仅存
本地归档残档，无法作为测试载体。当前服务器顶会话即上述 412 条仲裁会话。

**方法**：screencap ~400ms/帧 × 2.5s 注入慢拖（`input swipe`，路径 y≤1900 避
MIUI 手势区），PIL 相邻帧差分（≥8 灰度差像素占比）。五个方法格：

| 格 | 结果（帧差序列） |
|----|----|
| 稳态近底 × 下(翻旧) ×3 | 47/42% → 0.02% → 0 → 0（每轮前 2-3 帧爆发后尾帧全零） |
| 稳态近底 × 上(向新) ×3 | 36/47/11% → 0（同款爆发+冻结） |
| 深中段（15 次快翻后）× 下 | 40/46/17% → 0 |
| 深中段 × 上 | 38/44/24% → 0 |
| 冷启动进场窗口 × 下（0.6s 后即拖） | 69/39% → 0 → 0 |

**判词**：①**零次中段全死帧**——#245 本体（真手指「拖不动」）仍未复现，与
八轮结论一致；②**两方向完全对称**的「前半程爆发 + 后半程零移动」= 注入手势
平台批处理伪影（2.5s 手势合并成 2-4 个巨 delta 提前送达）——即 `input swipe`
结构性无法模拟真手指的连续位移流，**注入慢拖不是检测「手指动列表不动」类
bug 的有效仪器**；③冷启动窗口拖动也不「全灭」（八轮该现象勘误后再获佐证）。
④本轮 y≤1900 注入拖动全部有效（手势区坑未现）。

**结论**：卡维持用户侧观察项——唯一激活路径 = 用户真人复现时记录列表位置
（是否贴底/中段）+ 录屏 10s + 注明会话与消息位置。
