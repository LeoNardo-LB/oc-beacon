## 四、长会话分页（#172）——存储不兼容，降级（如实记录）

决策树执行记录：

1. 隔离 HOME 全新启动 → storage 空（/session = []）→ 无法提供长会话历史。
2. **只读挂真实数据尝试**：sqlite `.backup` 只读快照用户真实库（~/.local/share/opencode/opencode.db，167MB）到 /tmp/v1home/data/opencode/（快照含 **322 sessions / 20387 messages**，V2 布局 session_v2/session_message 表），V1 指向该库启动：
   ```
   Error: Unexpected error
   Database is not empty and has no session table
   EXIT=1
   ```
   → **V1/V2 存储不兼容实锤**（V1 要求 session/message 表，V2 库只有 session_v2/session_message；与 docs/research/issue-1-v1-connect-speed-2026-08-21.md 记载一致）。快照随后删除，未触碰原库。
3. 造长会话历史需向服务器写数据（发消息）——**任务纪律明令禁止**。

**结论：#172「加载更早」V1 本地 {id,time} 锚点游标与 loadAround 快速定位无法在真机落地（存储不兼容 + 只读纪律），JVM 契约测试仍是唯一覆盖。** 本会话降级为：探测验证 + 空 UI 走查（§三 + §五）。
