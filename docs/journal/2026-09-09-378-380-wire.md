## §二 DSH 服务器契约取证（#378 前置 wire 级分析，2026-09-09）

取证方式：部署包源码逐项定位（子代理，全部结论带 文件:行 证据）。包根 R = node_modules/@deepseek-ai/（dsh 本体仅 launcher，服务器代码在 dsh-* 插件包）。

### 传输架构
- 无独立 REST/SSE 面：RPC 统一 POST /api/<endpoint>（client-request/server-response JSON envelope，R/dsh-client-connection/lib/index.js:479-492）+ WS /api/remote.mux 流式多路复用（R/dsh-api-gateway/lib/types/stream-protocol.js:3,155-196）。
- payload 必须是 {args:{…}} 按参数 wire 名 keyed（gateway/index.js:930-940）；多余/缺失参数 → gateway/arguments-invalid（:1045-1056）。

### 关键契约（对 #378/#380 有直接影响的五条）

1. **事件信封**：{type, seq, time(epoch ms), data}——每 session 单调连续 seq（0 起），follow 首帧 snapshot 带 cursor，seq 跳号即 gateway/internal（dsh-session/types/types.d.ts:232-234,435-441；history.js:176-210）。**流内时序定位有精确权威键。**
2. **session/page 历史包含全部原始日志事件**：分页锚点只数 user/assistant 消息（MESSAGE_TYPES，history.js:60），但返回区间内 raw 事件切片（:333-355）——command/run|done、compaction/*、tool/call|result 全在（known-event-types.js:29-33）。**「重进丢卡」不是服务器缺数据——客户端解析侧过滤掉了。**
3. **command/run|done**：{commandId, name, args?} / {commandId, kind, text?}——commandId=cmd-<token>-<n> 单调配对键；log-only 不进模型表面；语法错误/未知命令不入档（dsh-commands/index.js:303-321,375-391）。**受理行→run→done 三态与 commandId 配对天然支撑单卡演化+历史重建。**
4. **压缩族=compaction/start|summary|end|prune**：以 compactionId(+sourceCommandId) 锚定；summary 内容在 data.summary（ContentBlock[]）+ shadowedRange/shadowedSeqs；表面替换由**紧邻其后一条新 user/message** 以 surfaceOp:{op:replace,start,end} 执行（契约性邻接，dsh-compaction/types/types.d.ts:21-98）。**压缩实体入流有完整数据支撑：summary 卡锚定自身 seq，旧区间按 shadowedRange 折叠。**
5. **整行解析**：正则 /^\/(?<name>[a-z][a-z0-9_-]*)(?=$|[\t\n\r ])/ 拆名，余下原文 verbatim 作 rawInput（无引号处理、无 token 拆分，dsh-commands/index.js:96-104）——与 app 端「首段空白切割、args 原样保留」语义一致，客户端无需预解析。

### commands/list 元数据
{name, description, input?{hint, images?}}——无参数 schema、无 client/server 类型标记；唯一能力位 input.images（typert.remote-client.js:23-30）。app 现映射（input.hint→hints）已对齐，无需改动。
