# §1 取证与根因定罪（2026-10-19 01:20）

## 证据链
- r1036_full.log:94245+（真机 houji，dev 包，512MB largeHeap）：主线程 OutOfMemoryError——Failed to allocate a 396416 byte allocation，target footprint 536870912（0% free）。
- 崩栈：StringFactory.newStringFromUtf16Bytes ← StringBuilder.toString ← com.mikepenz.markdown.compose.MarkdownExtensionKt.MarkdownElementInternal(MarkdownExtension.kt:64) ← MarkdownKt.StreamingMarkdownSuccess(Markdown.kt:420) ← ReasoningBlock 展开态流式 ← CardExpandReveal。
- 396416B = 198,208 UTF-16 字符 ≈ 崩溃时刻全文档长度（MDPilot 末条日志：stable=2480 tail=1 total=198200）——失败分配=全文档 toString。

## 根因（库 0.45.0 源码钉死）
- MarkdownExtension.kt:64：`val model = remember(node, content, typography) { MarkdownComponentModel(content = content.toString(), ...) }`——content 是 StreamingMarkdownState.content（**全文档 StringBuilder，恒等实例**）。
- 每个毕业稳定元素在首次组合时把**毕业时刻的全文档快照**物化为 String 并被 remember 槽持有至组合销毁。
- **保留内存 = O(N²)**：N 个毕业元素 × 各自快照（≈毕业时文档长度）。
- 数值验证：2480 元素、末态 198200 字符 → Σ ≈ 2480 × ~99K × 2B ≈ **491MB ≈ 512MB 上限 → OOM**（吻合）；对照 r1034（133K px 存活）≈ 1900 × 66.5K × 2B ≈ 253MB < 512MB 存活——二次曲线过阈跨 r1034→r1036 完全一致。
- 顺带解释 r1037（终态重展开正常）：静态路径 content 为 String，String.toString() 返回 this 零拷贝——**仅流式 StringBuilder 路径有平方保留**。
- 次要通道（非本案主因）：不稳定尾每次 append 重解析产生新 ASTNode 实例 → remember miss → 全文档 toString（每批 ~400KB 瞬态垃圾，2-3 元素/批）。

## 根修设计（app 侧，正确层级=保留语义本身）
- 0.45.0 的 `Markdown(streamingMarkdownState=…)` 重载自带 `success` 槽；app 现两处调用（MarkdownContent.kt:864 pilot / :889 cachedTerminal）均未传 → 落默认缺陷路径。
- 修法：自备 success 槽 `StreamingMarkdownSuccessBounded`——复刻库 Column+元素派发结构，但 MarkdownComponentModel 携带**元素自身文本**（content.subSequence(node.startOffset, node.endOffset)）+ **偏移重基节点**（ShiftedASTNode 委托包装，start/end/children 平移 -node.startOffset；parent=null=重基坐标系根语义）。保留内存降为 Σ 元素文本 = **O(总文本) 线性**。
- 稳定元素 remember 键仍为 node 实例（与库同构失效语义）；不稳定尾新实例天然 miss 重提取（瞬态成本从全文档降为元素文本）。
- app 自定义组件无 .parent 消费（grep 证伪）；库组件经 getTextInNode/getUnescapedTextInNode(content) 绝对偏移取文本——重基后自洽。
- 两个调用点都换（cachedTerminal 复用 pilot 的 StringBuilder state，冷重展开同险）。

## 复现协议（红）
- 巨流场景：MOCK_LINES≈2600（≈262K 字符，行 ~100 字符 + \n\n=逐行独立段落=即刻毕业 → ~2600 稳定元素，结构同 r1036 经 splitOversizedParagraphsByPosition 逐行空行化后的真实思考流）。流式早期展开思考卡并保持。
- 断言：无 OOM/进程存活 AND 峰值 Java Heap ≤ largeMemoryClass 40%。修复前预期 OOM 或峰值 >85%。
