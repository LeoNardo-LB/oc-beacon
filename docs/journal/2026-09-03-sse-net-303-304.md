## #303 会话生命周期事件被 ownership 单飞门吞——同后端双配置列表不实时

### Phase 1 红回路

`curl POST /api/session（唯一 title）→ 6s → uiautomator dump 列表 grep` ——首轮 0 命中（红，确定性，~10s）。

### Phase 2-4 定罪链（打点 [303dbg] 两层）

- 服务器广播实证：PC 侧 `curl -N /api/event` 订阅+建会话 → `session.created` 帧到达 ✓（V2 wire：
  data 扁平、**无 time 字段**——parser `decodeSessionCompat` 以 now 填充，不沉底）。
- app 接收实证：`[recv] SessionCreated` 双流各一（同一 PC 双入口：reverse 隧道 Host-4199 + LAN 直连 248）。
- 断链定罪：`dispatch → serverA` ✓ / `dispatch → serverB` ✓ / `handleSessionCreated → 仅 serverB`——
  **EventDispatcher.processEvent 的 ownership 拦截**（StreamingOwnershipRegistry.claim=putIfAbsent
  先到先得）：LAN 直连物理快几 ms **永赢 claim** → 展示中服务器（隧道侧）的生命周期事件被当
  「重复」丢弃 → 列表不实时；REST 下拉刷新走 setSessions 不经此路径 → 能恢复（症状闭环）。
- 三轮实验全直连赢（系统性非随机）；issue #6 报告者环境的可能同源（待查其是否双配置）。

### Phase 5 修复（100003f2）

- **Created/Updated/Deleted 豁免拦截**（幂等：trackSession 集合并集+列表 set/replace/移除；
  双配置各自处理=各自归属呈现——用户配双入口即期望各自列表显示）。
- **claim 总是执行**（豁免类首达即占位——后续非豁免流式事件仍按所有权拦，防双倍 delta/message）。
- 高频流式事件去重保留（原设计意图不变——legacy 测试改造：`second server events skipped` 的
  事件载体 SessionUpdated→MessageUpdated，保留原拦截语义断言）。

### Phase 6 E2E 绿 + 仪器教训

- **视口假象坑**：豁免修复后 dump 仍 0 命中——实为 LazyColumn 视口冻结（新会话在顶、视口停在旧位置
  只渲染可见项；dump 头部恒为旧会话=铁证）。**修正回路：dump 前先滚顶**。修正后 e2e303g/f/e 及
  终验 final-xxx 全部按时间序登顶 ✓；VM 层 n=50→51 发射实证（[303dbg2]，已清理）。
- 干净包终验：建会话→6s→滚顶→dump **新会话列表最顶** ✓。
- 单测：`EventDispatcherOwnership303Test` ×2（created 双达/deleted 跨配置清——顺带实证
  handleSessionDeleted 的全映射清理语义正确）+ legacy EventDispatcherTest 全绿 + 全量 `--rerun` 绿。
