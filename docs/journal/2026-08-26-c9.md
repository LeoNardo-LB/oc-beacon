## V6 人工验证清单（真机，V6 域——通知行为应与改造前零变化）

1. **后台轮次完成通知**：app 退后台，会话跑完一轮 → 任务渠道系统通知
  （标题「轮次完成 · 会话名」，正文=最后一条用户消息；静音开关对应
   tasks/tasks_silent 渠道）
2. **轮次完成提示音**：停留在该会话页面（前台聚焦）等轮次完成 → 会话内
   提示音/震动（无系统通知）；离开会话页面后退后台 → 恢复系统通知
3. **权限请求通知**：后台触发权限请求 → 权限渠道通知；开启「自动允许权限」
   开关后 → 无通知直接自动应答 always
4. **错误通知**：后台会话出错 → 错误通知只弹第一条（连续错误静默）；
   发新消息或轮次成功后恢复
5. （顺带）设置页「发送测试通知」仍能弹出（SettingsViewModel 签名变更路径）

## 偏离与理由

- 走查提示"auto-allow 已在 C7 迁到 PermissionAutoApprover 从那复用"——实测
  processEvent 内的 auto-allow 是**设置总开关**（reply "always"，跳过通知），
  与 C7 的规则式 maybeAutoApprove（reply "once"，EventDispatcher 分发点驱动）
  是两个机制；开关机制随通知路由迁入 coordinator，规则式未动未复制
- 端口形态选「注入通知端口」（任务书给出的两种形态之一）而非 sealed action
  返回值：SessionIdle 分支内含收敛查询（compute/check assistant id），本就
  需要查询协作者；端口 fake 断言动作序列即可覆盖三态矩阵，样板更少
