## 1. 结论

断连期间结束的任务，在重连后被 `session/control` 权威基线**正确收敛为终态**；本地镜像**未残留**「运行中」。

- 目标任务 `sleep 600`：T0 连线上显示 `运行中` → 断连期间自然结束 → 重连后基线重推，卡片变为 `完成 · exit code: 0`（bounds 与命令文本同卡）。
- 全程**未执行**下拉刷新、未重进会话；收敛完全来自重连后的 baseline（`JobsSnapshot` 全 session 一批），证明基线覆盖了终态任务，不会遗漏会话键。
- 对照组：真正仍在运行的 emulator 任务保持 `运行中`（正确）；`sleep 900`/`sleep 150` 为 `完成`、`sleep 1500` 为 `已终止`（均正确）。

## 2. 前置异常与处置（如实记录，不影响判定有效性）

**原 `sleep 150` 窗口错过**：接手时宿主 `sleep 150` 仅剩约 141s，且 App 当时连的是 **OpenCode `127.0.0.1:4199`**（会话列表全是 OC 会话，日志 `Ktor Client … 4199/api/form/request`），**看不到** `session-94365bc9`；即使进入也会打到错误的服务器类型。故先以 DSH debug intent 重指向 3080（`--es debug_server_type dsh --es debug_token <token>`，见 `MainActivity.handleDebugProfileIntent` 第 463/472 行），并请父代理在 `session-94365bc9` 内新起后台任务 `sleep 600`（jobId=bash-11，宿主起始 **01:44:30.144**）。

因此本测试的「断连期间结束」用的是一枚**新任务**（`sleep 600`），时序完整满足边界条件：T0 运行中 → T1 断连 → 任务在断连期间结束 → T2 恢复 → 观察基线。**非 INCONCLUSIVE**。

| T2post 01:55:16（重连后） | `[74,1031]bash · sleep 600 · exit code: 0` | `[98,968]完成` |

关键判定证据：
1. **推送机制**：重连后 `session/control` 基线以 `JobsSnapshot` 全 session 一批重发，其中**明确包含 `sid=session-9436`**（`logcat-reconnect-baseline.txt`）→ 基线不会遗漏「刚结束任务的会话」。
2. **终态随基线到达**：基线携带终态任务（历史 `sleep 900/150` 为「完成」、`sleep 1500` 为「已终止」），故 `sleep 600` 的 `exit code: 0` 也由基线提供；镜像被整快照 last-wins 覆盖。
3. **无人工干预**：T2→T2post 期间未下拉刷新、未重进会话；收敛纯由自动重连基线完成。
