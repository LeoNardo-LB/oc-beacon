## B. #402 冷却不再误计连接级失败（OpenCode）

### 过程

1. 01:32:21 OpenCode debug intent 启动，`Debug channel → SessionList`，已连（无断连横幅）。
2. 01:32:28 进入有内容会话「一加一等于二的提问」（转录含「轮次 14 · 3ms · 1 步 · 0 个工具」等，非空）。
3. 01:33:00 `logcat -c`；**01:33:00.806** `adb reverse --remove tcp:4199`。
4. **01:33:15.817（+15s）第一窗**：无任何 SSE 日志、cooldown 计数 0 —— 既有 SSE 连接在 reverse 被移除后未立即断开（约 25s 后开始反应），15s 不足以出现 5 次连接失败，故延长观察。
5. 设备侧首个失败 **01:33:25.645**：`SSE connection attempt #1` → `java.net.ConnectException: Failed to connect to /127.0.0.1:4199 … ECONNREFUSED` → `[Host-4199] Reconnecting in 1000ms (attempt #1)`。
6. 01:33:26.7 → 2000ms；01:33:28.7 → 4000ms（**指数退避**）。持续多轮。

### 关键计数（截至恢复前 `logcat-B-full-after-remove.txt`）

```
Entering SSE cooldown after : 0
SSE in cooldown            : 0
Reconnecting in            : 8+
backoff 值分布             : 1000ms ×6 / 2000ms ×6 / 4000ms ×5
失败类型                   : java.net.ConnectException ECONNREFUSED（连接级）
```

- 阈值对照（源码 `SseClient.kt:313-314`）：`MAX_CONSECUTIVE_TIMEOUTS = 5`、`COOLDOWN_DURATION_MS = 300_000`（5min）。本次连接级失败轮次 **≥8，远超 5**，却**未**进入冷却 → 修复生效。
- `Reconnecting in` 序列 1000→2000→4000 呈指数递增（源码 `calculateBackoff`：base 1000 × 2^(attempt-1)，cap 30s / normal）。

### 恢复时延

- 01:34:00.953 恢复前 dump：命中横幅 `text="服务器已断开，正在重连…"`（`dump-B-disconnected-banner.xml`）。
- **01:34:03.074** `adb reverse tcp:4199 tcp:4199`。
- 轮询捕获 `I SseConnManager: Connected to server 10afe73c-67e8-4631-88c1-b2fc9200fecc`，**实测耗时 2038ms ≈ 2.0s**（宿主时钟，含 2s 轮询粒度）。设备钟（慢约 0.73s）记录 01:34:02.354。
- 恢复后 dump：**无**「服务器已断开」横幅（`dump-B-after-reconnect.xml`）。

**B 判定：PASS** —— 未出现 cooldown 行；连接级失败走指数退避；恢复 ~2.0s ≤ 60s（旧行为 ~4m38s）。

### 观察（不影响判定）

- 日志中存在**两条交错的 Host-4199 重连序列**（attempt 计数多次回到 #1），疑为第二条连接/探测路径并发触发；本次未定性、非本修复面，但导致退避未观察到 >4000ms 的档位。连接级失败「不计冷却」的结论不受影响（两序列共用 per-server tracker，均无 cooldown）。
