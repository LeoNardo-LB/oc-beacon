## 机制分析（代码层，只读）

`app/src/main/kotlin/dev/leonardo/ocbeacon/ui/screens/chat/components/SheetGestures.kt`：

- `sheetContentGestureIsolation()` 仅在 sheet 内容根挂单个 `nestedScroll(SheetGestureIsolation)`；
- `onPostScroll`：`available.y > 0`（向下剩余量）就地消费；`onPostFling`：向下剩余速度 `available.y > 0` 就地消费；
- **无任何 server type / V1·V2 分支**；
- 手柄 `SmallSheetDragHandle` 12dp 位于隔离连接之外 → 手柄拖拽直达锚定拖动，收起能力保留。

因此「V1 特有分叉」在代码上不存在；但隔离依赖**可滚动子节点派发 nested scroll**：列表 `LazyColumn`（y≥706）派发的事件会被消费，而标题行/手柄/空白带不经过该连接，直接进入 sheet 的 anchoredDraggable → 收起。这与实测边界 y≈706 吻合。

## 未复现说明与尝试

- V1 共执行 **18 次内容区手势**（含列表中部、列表已在顶部、极端 30/50ms 高速 fling、慢拖、向上 fling、打开加载窗口 0/+0.15s），**0 次收起**。
- 已尝试覆盖「加载窗口」「列表到顶惯性外溢」「极高手速」三类最可能的泄漏场景，均未触发。
- 若原报告者实际起点落在标题行带（y≈490–706）或手柄，则现象可复现，但归类应为「手柄/标题带下滑」，**不是内容区 fling**；且 V2 同样如此。
- 未做：真手指（物理设备）手感复测（模拟器 input swipe 不能 100% 等价真实 touch 采样）；未采集 perfetto 触摸事件；未在真机 houji 上复测。若需以「真手指体感」定案，须人工验证。
