# AGENTS.md — docs/learning 学习专区

> **⚠️ 目录定位声明（最高优先级）**
>
> 本目录是**所有者的 Kotlin / Android 个人学习专区**，仅此而已：
>
> - ❌ **不包含任何业务语义**——这里的文档不描述 oc-beacon 的功能、设计决策或架构真相
> - ❌ **不承接任何功能性文档**——业务文档一律放 `docs/` 根下对应主题文件，禁止迁入或新建于此
> - ❌ 本目录内容**不构成开发规范**，不得被业务代码、CI、脚本引用；不得进入构建链
> - ✅ 本目录中的代码示例仅为教学用途；引用本项目真实代码时必须标注来源且只读不改

---

## 1. 这个目录是什么

所有者背景：Java 后端开发者，懂一些前端，通过 vibecoding 产出了本项目，现希望系统学习 Kotlin 与 Android 开发。学习策略（已与所有者确认锁定）：

| 决策点 | 结论 |
|--------|------|
| 目标 | 两阶段：先读懂本项目 → 再进阶独立开发 |
| 路径 | 项目驱动式，数据层先行（Java 舒适区 → Compose 新领域） |
| 内容 | 通用概念用最小可运行示例讲解 + 每章「在本项目中对应」真实代码佐证 |
| 实践 | 只读不练 + 每章「观察任务」输出倒逼输入 |
| 节奏 | 碎片+周末大块，单章 15–30 分钟阅读量 |

## 2. 文件结构


## 3. AI 填充章节时的写作规范（MUST）

当所有者要求填充/续写某章时，**必须遵守**：

1. **章节模板**（顺序固定）：

   ```markdown
   # chNN · 章标题
   > 阅读时长：约 XX 分钟 ｜ 前置：chXX
   ## 学习目标（3-5 条，可验证）
   ## 概念讲解（通用最小示例，Java 对照优先）
   ## 在本项目中对应（真实路径:行号，写入前必须重新验证）
   ## 观察任务（2-3 个，只读代码即可完成，产出文字答案）
   ## 常见坑
   ## 我的笔记 / 疑问（留给所有者，AI 不得代填）
   ```

2. **读者画像**：Java 后端。凡 Kotlin/Android 概念优先给 Java 对应物（如 data class ↔ record、StateFlow ↔ Reactor、Hilt ↔ Spring DI），禁止按零基础教学口吻展开。
3. **项目佐证真实性**：「在本项目中对应」的每个 `路径:行号` 必须在写作当时实际读取验证；行号易漂移，格式为 `函数名/类名（路径:行号）`，以符号名为准。
4. **篇幅纪律**：单章正文控制在 30 分钟阅读量内；超了就拆章，不要压缩字号式堆砌。
5. **只读红线**：教程示例代码不得写入 `app/src`；不在业务代码中加"教学注释"；不改任何业务文件。
6. **语言**：中文。
7. **完成一章后**：更新 `PROGRESS.md` 中该章状态为「📝 已就绪」（注意：不是「✅ 已学完」——学没学完由所有者打卡决定）。

## 4. 所有者使用方式（给人看的说明）

- 断片后接不上？→ 看 `PROGRESS.md` 上次打卡位置 → 打开对应章节末尾「我的笔记」回忆卡点。
- 要开始新的一章？→ 对 AI 说："填充 docs/learning 的 chXX"，AI 会按 §3 规范生成全文。
- 学完一章？→ 在 `PROGRESS.md` 打卡（改状态 + 记日期）。

## 5. 边界速查

| 场景 | 行为 |
|------|------|
| AI 被要求在本目录写业务/spec/规则文档 | 拒绝并指向 `docs/` 根对应位置 |
| 业务文档需要引用学习内容 | 禁止反向依赖；业务文档不得链接本目录 |
| 教程内容与业务架构文档冲突 | 以 `docs/architecture.md` 为准，教程只是教学快照 |
| 所有者在笔记区提问 | AI 可以在紧邻的「AI 回复」小节作答，但不得擦除原始疑问 |
