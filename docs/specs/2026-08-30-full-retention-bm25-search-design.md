# 本地全量保留 + BM25 对话内容检索设计（backlog #271/#272）

> 状态：**设计定稿（2026-08-30 用户逐题裁决）待实现**
> 用户裁决（拷问轮）：检索范围两级（全局+当前会话）· 索引仅 user/assistant 正文 · FTS5 unicode61 单字分词起步 · 改造会话列表既有搜索框统一入口（标题命中与内容命中分类聚合）· 增量索引+版本号重建 · 过滤全上（会话/角色/时间范围）· **纯本地持久化数据检索**（不依赖服务器端点）· **本地全量保留**（移除冷存桶自动淘汰/取消 reasoning 截断/工具输出维持 500 预览/首开自动 drain 全量历史 + 会话同步状态标识与长按触发）· 删会话=本地全清（维持）

## 1. 现状盘点（源码实证 2026-08-30）

- **热表**：每会话最近 1000 条（`SESSION_MESSAGE_LIMIT=1000`），溢出 prune——**prune 前先 zstd 归档**，热层不丢数据。
- **冷存桶**（archive_buckets，v2+）：1 天窗/200 条/512KB 分桶；**每会话 200 桶保护上限，超出删最久未访问桶（`enforceArchiveLimit`）——唯一的自动永久删除点**。
- **落库截断**（#79）：工具 part output/input/metadata 截 500 字符；**reasoning text 同样截 500**——冷存桶内容来自热表行，故截断版即归档版，全量只在服务器。
- **懒加载**：历史靠分页拉取（50/页，`persistOldBeyondWindow=true` 落热表）；SSE 增量写 `persistOldBeyondWindow=false`（窗口外跳过）；未翻到的历史不进本地。
- **删会话**：热表 FK 级联 + 冷存桶按 sessionId 清除——本地全丢（服务器端同时消失，语义一致）。
- **无任何 FTS 表**（ocbeacon.db v4）；会话列表搜索仅标题（#100，服务端+客户端双层）。

## 2. #271 全量保留

1. **移除冷存桶自动淘汰**：`enforceArchiveLimit` 的删桶逻辑去除（或常关），真·全量保留；设置页新增「存储占用统计」（按会话）+ 手动清理入口（按会话/全局）防失控。
2. **reasoning 取消落库截断**：`ToolOutputTruncator.truncateReasoningIfNeeded` 调用点移除——reasoning 纯文本压缩友好、体积中等，且重进后思考卡内容完整性与 #266 对账体验一致。
3. **工具输出维持 500 字符预览**（用户确认 c）：DB 体积大头；服务器重拉兜底（#79 既有权衡）；未来若要离线全量，冷存桶可加 zstd 全量列，不锁死。
4. **首开自动 drain 全量历史**：首次打开会话（或同步状态≠synced）时后台分页拉取全部历史（复用 `fetchAllMessages` 分页模式 + `persistOldBeyondWindow=true` 落库），之后靠增量维护；同步状态机：未同步/同步中/已同步（含 lastSyncAt）。
5. **会话同步状态 UI**：会话列表行内轻量标识（已同步✓/同步中/未同步 + 最后同步时间）；**长按菜单**新增「同步全部历史」触发单会话 drain（不新增会话级设置页）。
6. **删会话维持现状**：本地热表+冷存+索引全清。

## 3. #272 BM25 内容检索

1. **索引载体**：Room 旁建 **FTS5 虚拟表**（migration 原生 SQL 创建，不经 Room entity 管理，DAO 以 @RawQuery/room query 访问）——用 FTS5 内建 `bm25()` 排序与 `snippet()` 片段。tokenizer = `unicode61`（中文单字 token，零依赖；分词器为建表参数，将来换 trigram/ICU 只需重建）。
2. **索引内容**：user/assistant **text part 全文**（text part 落库本就不截断，天然全量）；reasoning/工具输出不入索引（用户裁决）。FTS 行按（sessionId, messageId, role）粒度，独立于热/冷分层——**入桶 prune 不删 FTS 行**，保证冷数据可搜；删会话按 sessionId 清 FTS。
3. **增量维护**：消息落盘事务内同步 FTS 行（delete+insert 该消息）；首装/升级/FTS 版本不匹配时全量重建（含冷存桶解压回填），版本号存 pragma/元数据表。
4. **查询**：`bm25()` 排序 + 过滤链（会话维度/角色 user|assistant/时间范围）；结果 = FTS `snippet()` 片段。
5. **交互**：改造会话列表既有搜索框为统一入口——输入即同时检索标题（现 #100 路径）与内容（FTS），结果**分类聚合展示**（标题命中区 / 内容命中区：会话分组 + 片段 + bm25 序）；点击内容命中 → 跳转会话 + 滚动定位该消息 + 高亮。会话内 Ctrl+F 式即时过滤为后续增强。
6. **纯本地**：检索全程不触服务器；数据源=本地持久化缓存（V1/V2 服务器无关，未来 DSH 会话入缓存即可搜）。

## 4. 非目标 / 风险

- 工具输出不入索引、不存全量（本轮）；离线完整工具输出=未来冷存 zstd 全量列。
- FTS 中文一元分词噪音：实测后若不足，重建换 tokenizer（已留版本号路径）。
- DB 体积：全量保留 + FTS 后体积上涨（zstd 冷存约 4-8x 压缩对冲）；占用统计+手动清理兜底。
- drain 网络成本：大历史会话首次打开几十页请求（仅一次）；可加设置开关（暂不做，实测再议）。
- CursorWindow 2MB：沿用既有 512KB 分桶约束。

## 5. 验收草案

- 单测：FTS 增量写/删除会话清理/重建版本迁移；归档不删路径；drain 状态机。
- V3 实机走查（Agent）：发长对话→立即搜索命中新消息；drain 一个从未打开的大历史会话→全局可搜；删会话→索引同步清除；占用统计数字合理。
- V6（用户）：搜索结果聚合观感、片段可读性、点击定位准确性；同步状态标识直觉性。
