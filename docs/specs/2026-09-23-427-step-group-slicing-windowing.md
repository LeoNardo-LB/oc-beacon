# #427 步组大内容切片 + 预测量 + 窗口化组合（成本根因修复）spec

> 状态：ready-for-agent（spec 定稿，未开工）。创建：2026-09-23，来源 #423 批次十一至十四取证链。
> 术语遵循 CONTEXT.md；实现不得引入补偿族方案（用户两次裁决先例）。

## Problem Statement

批次十四之后，步组展开/收起的钉位、震荡、位移问题已全部根治，但超大步组内容（数千至数万 px：30-60 行表格、多步工具输出）仍存在**成本与内容总高成正比**的一次性主线程重测冻结——展开的 ε 沉降与收起的原子闭合各付一次，4688px 实测 ~0.5-0.8s，20k px 级历史实测 3.6s。用户观感：点击后先「定住」再瞬间展开/收起；内容越大冻结越长，且低配设备更差。空闲预热只把这笔账挪早，没有减少它。

## Solution

步组内容的组合/测量/绘制成本改为**与可视窗口成正比、与内容总高无关**：内容按权重切成约一屏的片；每片高度空闲期预量入账本（宽度键控、持久化）；卡片内只组合视口附近相交的片。展开时高度从账本即时可得（幕布照常揭示），收起时只有窗口内的片参与重测。任意大小的步组：展开/收起等待有界、首开不冻结、二次零等待、滚动长内容如常流畅。

## User Stories

1. 作为聊天用户，我想展开含 30 行表格的步组时在 ~400ms 内看到幕布揭示，而不是先冻结半秒以上。
2. 作为聊天用户，我想收起超大步组的耗时同样有界，不随内容变大而变长。
3. 作为聊天用户，我想首次展开（预测量未完成时就点击）最多等一次**有界**（单片级）重测，且全程无位移、无闪白。
4. 作为聊天用户，我想二次展开零等待——高度账本直接命中。
5. 作为聊天用户，我想滚动浏览已展开的超大内容时只组合视口附近的片，滑动流畅度与内容长度无关。
6. 作为聊天用户，我想快速连点展开/收起时钉位不破、无震荡（批次十一至十四的全部铁律在新架构下保持）。
7. 作为聊天用户，我想折叠行顶部钉死、屏幕上其他元素纹丝不动——切片化不得改变钉位契约。
8. 作为聊天用户，小步组（权重低于切片阈值）的体验与当前版本完全一致（零回归）。
9. 作为聊天用户，旋转屏幕/折叠形态变化后，高度账本按宽度失效并重算，展开态位置不跳变。
10. 作为聊天用户，流式输出期间的行为不受本特性影响（步组属非流式域）。
11. 作为低配设备用户，我想超大内容的成本上限由我的屏幕尺寸决定，而不是由消息长度决定。
12. 作为低配设备用户，我想内存占用下降——窗口组合加高度缓存替代当前的全量 ε 保温组合树。
13. 作为聊天用户，我接受片边界处长按文本选择断裂的取舍（工具步骤内容，非正文散文），前提是写明且可预期。
14. 作为开发者，我想要一个纯函数切片器：按权重把步组内容在 PartGroup 边界切成约一屏的片，JVM 可单测。
15. 作为开发者，我想要高度账本：宽度键控缓存 + 跨回收持久化；总高=各片之和；冷缓存回退现有 ε 沉降。
16. 作为开发者，我想要真测与账本的差异走既有迟到增量配对通道，误差被单片高度封顶。
17. 作为开发者，我想要窗口化宿主：只组合视口 ±1 屏相交的片，纯放置语义，不引入嵌套滚动。
18. 作为开发者，我想让空闲预热收窄为「预量片高」并错峰执行（收编 #424/#425 的动机）。
19. 作为开发者，我想让结构裂变死代码（#426）随切片器转正一并清理。
20. 作为验证 agent，我想要切片器与账本的外部行为单测：边界划分、权重聚合、总高守恒、宽度失效、冷回退。
21. 作为验证 agent，我想要沿用既有真机取证方法论（绘制探针时间线、分带互相关、多模态目检）作为视觉不变量验收，主观手感仅留最终拍板一项人工。

## Implementation Decisions

- **四阶段交付，每阶段独立可验收**：P1 切片器（纯函数）→ P2 高度账本 → P3 窗口化宿主 → P4（可选）表级窗口化。P1+P2 先行合入即可兑现「二次展开零等待」。
- **切片器**：按字符当量权重（现有标定）在 PartGroup 边界贪心聚合，目标约 2200 权重/片（≈1 屏）；复活已退役裂变路径的切片语义作为基线，语义不变、宿主从列表条目移入卡片内部。
- **高度账本**：每片高度缓存，键=内容指纹+可用宽度；跨组合回收持久化（与引擎既有 finalH 缓存同机制）；总高=Σ片高；账本冷时回退现行整体 ε 沉降（正确性不依赖预热）。
- **窗口化宿主**：自绘布局节点，仅对与「视口 ±1 屏」相交的片做子组合；纯放置窗口（无嵌套滚动、无手势拦截）；片高未实 测时以账本值占位，实 测差异经引擎既有迟到增量配对消化（误差≤1 片高）。
- **引擎契约不变**：快照原子应用、单发配对位移、幕布纯绘制揭示、离底解跟随、程序化位移豁免——仅高度来源从「整体沉降实测」改为「账本求和」。
- **预热策略收窄**：从「全量 ε 组合保温」改为「空闲预量片高」（成本降低一个量级），并加错峰（一次一卡）——替代 #425 的队列方案并收编其动机。
- **小组零改动**：权重低于阈值的步组维持现行整体组合路径，不进入切片/窗口。
- **单体怪物取舍**：单个超大 part（如 60 行表格）作为不可分片时接受片内单体，配既有占位首帧；表内行级窗口化列为 P4 可选，不阻塞本卡。
- **无障碍取舍**：片边界长按选择断裂，工具步骤内容可接受（用户域内先例：折叠行摘要卡）。

## Testing Decisions

- 好测试只断言外部行为，不断言实现细节。
- **切片器（JVM 单测）**：边界覆盖（空组/单片/超重单片/恰好阈值）、聚合顺序稳定、幂等重切、流式豁免输入不变式。先例：条目构建与分片函数的既有 JVM 单测。
- **高度账本（JVM 单测）**：Σ 守恒、宽度变化失效、跨回收持久化往返、冷回退触发条件、差异封顶（≤单片高）。先例：引擎时钟与修正器的纯函数单测。
- **窗口宿主**：若组合级测试 seam 不足，以切片器+账本为单测边界，窗口正确性由真机验收覆盖。
- **真机验收（既有方法论）**：绘制探针时间线对账（集时长/位移/钉位恒定）、录屏分带互相关（零运动帧）、多模态目检（无白屏/无滑入）；性能预算断言：大卡展开集 ≤400ms、收起集 ≤400ms（含幕布），冻结 ≤单片组合成本。

## Out of Scope

- SSE 流式域任何改动（降级路径不动）。
- 结构裂变路径复活（批次十三已退役，仅切片器语义复用）。
- L0 解析预取线程池（#424 独立卡：接口衔接、另行实施）。
- 表内行级窗口化（P4 可选，若立项另立子卡）。
- 非步组大内容（轮次级分片已由既有分片计划体系承载）。
